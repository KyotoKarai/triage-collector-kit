---

## О проекте

**Triage Collector Kit** — это набор скриптов для быстрого сбора форензик-артефактов и данных инцидент-реагирования с конечных точек. Проект построен вокруг простого рабочего процесса:

```text
Обнаружена подозрительная активность
        ↓
Запуск скрипта-коллектора на хосте
        ↓
Артефакты сохраняются в структурированную папку
        ↓
Ручной анализ или импорт в платформу анализа логов
        ↓
Выявление подозрительных процессов, сетевых подключений, механизмов закрепления
```

Этот проект **не является** SIEM-системой или решением для постоянного мониторинга. Это инструмент быстрого триажа для специалистов по инцидент-реагированию и SOC-аналитиков.

## Возможности

### Коллектор для Windows

| Категория | Детали |
|-----------|--------|
| Процессы | Полный список процессов с командными строками, родительскими процессами, владельцами |
| Сеть | Активные соединения и слушающие порты |
| Службы | Службы с автоматическим запуском |
| Запланированные задачи | Все зарегистрированные задачи |
| Пользователи | Члены группы локальных администраторов |
| Журналы событий | Security, System, PowerShell, Sysmon, PrintService, TerminalServices |
| Сетевой дамп | Короткий сетевой дамп через `netsh trace` |
| Целостность | SHA256-хэши всех собранных файлов |

### Коллектор для Linux / Unix

| Категория | Детали |
|-----------|--------|
| Процессы | Полный список процессов с командными строками и родительскими процессами |
| Сеть | Активные соединения, слушающие порты, правила файрвола |
| Пользователи и сессии | Текущие сессии, история входов, неудачные входы |
| Закрепление | cron, at, systemd-юниты, init-скрипты, стартовые файлы шеллов |
| SSH | sshd_config, authorized_keys |
| Логи | syslog, auth.log, journalctl, auditd |
| Файловая система | Маунты, недавно измененные файлы |
| Пакеты | Список установленных пакетов |
| Сетевой дамп | Опциональный pcap-дамп через `tcpdump` |
| Целостность | SHA256-хэши всех собранных файлов |

## Быстрый старт

### Windows

```powershell
# Запуск от имени администратора
.\collectors\windows\Get-TriageData.ps1
```

Если политика выполнения блокирует скрипт:

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\collectors\windows\Get-TriageData.ps1
```

### Linux

```bash
# Сделать исполняемым
chmod +x collectors/unix/unix_triage.sh

# Запуск с правами root
sudo collectors/unix/unix_triage.sh
```

С сетевым дампом:

```bash
sudo collectors/unix/unix_triage.sh --pcap 30
```

Полный сбор:

```bash
sudo collectors/unix/unix_triage.sh \
  --pcap 30 \
  --recent-files \
  --app-logs \
  --full-journal \
  --include-shell-history
```

## Интеграция

Собранные артефакты можно импортировать в различные платформы анализа логов:

| Платформа | Статус | Описание |
|-----------|--------|----------|
| OpenSearch | Планируется | Дашборды и поиск |
| Elastic Stack (ELK) | Планируется | Полная интеграция с ELK |
| Grafana Loki | Планируется | Легковесный просмотр логов |
| Wazuh | Планируется | Интеграция с SIEM |
| Graylog | Планируется | Управление логами |

Подробнее в [Руководстве по интеграции](docs/LOG_INTEGRATION.ru.md).

## Примечание по безопасности

Эти скрипты собирают чувствительные данные, включая:

- Историю входов пользователей
- Информацию о процессах и командных строках
- Сетевые соединения
- Конфигурационные файлы
- Историю команд оболочки (при включении соответствующей опции)

**Не публикуйте собранные архивы в открытом доступе.** Храните их безопасно и передавайте только авторизованному персоналу.

Подробнее в [SECURITY.md](SECURITY.md).
